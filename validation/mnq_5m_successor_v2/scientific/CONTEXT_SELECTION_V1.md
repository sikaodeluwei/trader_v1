# Independent explicit-context annotation policy 1.0

Status: methodology only. No actual successor contexts or answers are supplied here.

## Inputs and independence

Use only the ten frozen OHLCV windows, their source/clock bindings, approved course-definition specifications, the independent annotation schema and approved independent hierarchy method. Do not expose production modules, project results, comparison outcomes or implementation-informed audit notes to the independent author. Root/implementation agents that saw production internals are not independent oracle authors with that same context. A fresh allowlisted preparation workspace must be used later. Source/provider limitations remain visible; unverified upstream data is not exchange-authenticated truth.

## Predeclared coverage register

Before annotation, list requirements for state.uptrend, state.downtrend, state.non_trend, state.insufficient; BMS confirmed/pullback-only/not-a-pullback; SMS confirmed/parent-continued/pullback-only/pending; strict wick break versus equality; invalid canonical references; ambiguous competing OHLC crossings; directional MEDIUM/LONG anchors and absent anchors. Report SHORT/MEDIUM/LONG and direction where applicable, including later structural confirmer provenance. The hierarchy protocol separately covers isolated/deformed points, unresolved potentials, normalization, suppression and promotion. Important missing real-data branches may be covered by reviewed synthetic course-rule fixtures.

The list is a coverage checklist, not an instruction to force natural events or create segments from anticipated production outputs. No required count of profitable/trading outcomes exists. No automatic selector is implemented or implied.

## Reproducible annotation and eligibility

1. Independently reconstruct canonical same-level structures from each raw window in the unchanged fixed window order w01..w10. Preserve exact source indexes/prices, confirmation basis, right-side structural evidence, suppressed points and unresolved potentials. Do not infer intrabar path, skip offending points or promote suppressed vertices.
2. The annotator explicitly proposes coherent analytical segments and structural levels, documenting course-based rationale. Parent trends, origins, pullbacks and creators are explicit choices; the course does not define a unique automatic selection. Reproducibility consists of frozen numeric choices, rationale, eligibility evidence and expected answers under fixed rules; it does not claim any analyst must choose the same discretionary segment.
3. Record candidate membership and alternatives before any production output. Use source window order and numeric segment bounds/level/boundary tuples to give the selected records a stable order; assign stable IDs. If eligible alternatives remain, preserve them or mark ambiguity rather than choosing retrospectively. A reviewer verifies that rationale is independent and definitions support the chosen interpretation. That eligibility review does not consult production results.
4. Primary state contexts use inclusive in-window segment bounds and only canonical vertices of the requested level. Preserve all selected same-kind relationships. Equality, interruption and insufficient points are evaluated under the existing facade contract; do not relabel unavailable as NON_TREND. Deliberate negative cases are labelled in annotation rationale and have exact INVALID/UNAVAILABLE expected outputs.
5. BMS: exact origin/prior-extreme/pullback indexes must resolve uniquely at that level. For valid directional parent contexts, preserve origin < prior extreme < pullback, the defined kinds/prices and parent end = prior extreme. SMS: creator < trend extreme, coherent kinds/prices, and parent end = trend extreme. Do not invent a creator-selection rule when the definition does not determine one; document the explicit choice or unresolved ambiguity.
6. Dense observation horizon is fixed through window end: BMS after the supplied pullback; SMS after supplied trend extreme. Record the first decisive strict wick crossing. Equality is a touch. A candle crossing competing bounds cannot determine intrabar order and must remain INVALID with ohlc_intrabar_order_ambiguous. Do not change the horizon to obtain a preferred event. Empty suffix/pending is legitimate. Pivot location is not live knowability time.
7. For a directional MEDIUM/LONG segment, independently label the earliest eligible canonical SHORT low (uptrend) or high (downtrend) inside the inclusive segment as the descriptive anchor, if present. Preserve its complete SHORT source provenance separately. It never changes selected-level points, state, BMS, SMS or promotion. For SHORT, unavailable/nontrend or absent candidates, expected anchor is null.
8. Fill complete semantic expected results in the same canonical projection as the implementation contract: request; selected_points with level/point/nested source_vertex; market_state; BMS; SMS; trend_start_anchor. Prices are canonical exact decimal strings. Preserve actual status/reason and broken boundary/event indexes. No guessed answer is allowed. Unknown teaching definitions are specification ambiguities, not an excuse to manufacture labels.

## Absent and ambiguous natural cases

For every predeclared requirement, coverage accounting records covered, absent or ambiguous, selected context IDs, rationale and a synthetic fixture reference where needed. Covered means identified independently in source, not production agreement. For absent rules, include no invented natural context; reference the synthetic fixture and state that real-data coverage is absent. A fixture reference is an obligation, not proof that the fixture was executed; the final scientific review verifies its test evidence. For ambiguity, freeze all admissible interpretations or an explicit unresolved ambiguity record outside scored contexts before production. The current context checkpoint supports exact machine-scored unambiguous records; it does not decide discretionary course ambiguities.

After all ten are inspected independently, publish the coverage/absence register without project results. Use existing synthetic tests for missing rule branches. Additional acquisition needs concrete evidence that a scientific requirement cannot be met by these windows plus synthetic fixtures; none is currently established.

## Freeze and handoff

Freeze the selection policy hash, all source bindings, ordered numerical contexts, rationale, coverage register and expected projections through freeze_contexts. Preserve its manifest hash externally. Review complete context membership and all ten hierarchy oracles, then freeze one stage inventory before production. Production receives only blind-requests.json with its external hash and frozen sources; it receives no selection rationale, coverage outcomes, expected answers or oracle module. No context may be added, removed or reinterpreted after comparison merely to improve agreement.

This policy prepares independent work. It selects no actual segment, computes no oracle answer, and authorizes no production run.
